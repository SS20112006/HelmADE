# Task 1.5: Alocador Dinâmico de Portas de Servidores Locais (Módulo 2) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar o motor de deteção e reserva dinâmica de portas de rede TCP em Rust com `std::net::TcpListener`, alocando portas sequenciais livres e gerando variáveis de ambiente (`PORT=300X`, `VITE_PORT=300X`) por painel de enxame (*swarm grid*), evitando colisões `EADDRINUSE` na execução simultânea de múltiplos servidores locais.

**Architecture:** Módulo `src-tauri/src/network/port_allocator.rs` gerindo um pool thread-safe (`PortState`) de portas no intervalo padrão `3001..3100`, integrado ao estado gerenciado do Tauri 2.x via comandos IPC (`allocate_swarm_port`, `release_swarm_port`, `get_swarm_env_vars`), serviço TypeScript (`portService.ts`) e integração com o Zustand store (`useGridStore.ts`).

**Tech Stack:** Rust (`std::net::TcpListener`, `std::sync::Mutex`, `serde`) · Tauri 2.x State & Invoke API · TypeScript · Zustand · React 19

**Spec:** `docs/ROADMAP.md` § Task 1.5 · GitHub Issue #18 / #8

## Global Constraints
- Proibição absoluta de `git stash` e `git stash pop`.
- Zero novas dependências de crate: usar exclusivamente a biblioteca padrão do Rust (`std::net::TcpListener`, `std::collections::HashMap`, `std::sync::Mutex`).
- Thread-safety: o alocador deve ser acessível com segurança a partir de múltiplos comandos concorrentes do Tauri (`Arc<Mutex<PortAllocator>>` via `tauri::State`).
- Sanitização rigorosa de identificadores de swarm para evitar injeção.
- Resiliência: se uma porta no intervalo estiver ocupada por uma aplicação externa do utilizador, avançar automaticamente para a próxima porta livre.
- Testes unitários comprovando reserva livre de colisões para 16 grelhas concorrentes.
- Commits atómicos seguindo a convenção Conventional Commits 1.0.0.

## Review Focus
1. **Port Collision Prevention**: Garantir que duas grelhas simultâneas nunca recebem a mesma porta TCP.
2. **External Conflict Tolerance**: Se uma porta (ex.: 3001) estiver em uso por outro processo do sistema, o algoritmo salta automaticamente para a primeira disponível.
3. **Idempotent Swarm Allocation**: Se a mesma grelha requisitar uma porta múltiplas vezes antes de liberar, retorna a mesma porta já reservada.
4. **Clean Release**: Ao fechar uma grelha, a porta volta ao pool e fica disponível para a próxima sessão.
5. **Environment Variable Generation**: Retornar mapa completo de variáveis de ambiente padrão (`PORT`, `VITE_PORT`, `SERVER_PORT`) pronto para injeção no PTY.
