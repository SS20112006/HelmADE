# Task 1.4: Gestor de Symlinks de Dependências com Zero Desperdício de Disco (Módulo 2) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar o gestor automático de symlinks em Rust para diretórios pesados de dependências ignorados no Git (`node_modules/`, `.venv/`, `target/`, `.cargo/`), interligando o repositório principal com cada Git Worktree recém-criado (`.helm/worktrees/<id>`), assegurando cold-boot instantâneo (<200ms) e consumo zero de gigabytes adicionais de disco.

**Architecture:** Módulo nativo Rust `src-tauri/src/git/symlink.rs` com deteção e ligação simbólica idempotente, integração no ciclo de vida de worktrees (`create_worktree` / `remove_worktree`), exposição via comandos Tauri IPC (`symlink_worktree_dependencies`) e tipagem/serviço frontend em TypeScript (`symlinkService.ts`).

**Tech Stack:** Rust (`std::os::unix::fs::symlink`, `std::fs`, `serde`) · Tauri 2.x Invoke API · TypeScript · React 19

**Spec:** `docs/ROADMAP.md` § Task 1.4 · `docs/adr/2026-10-06-0002-git-worktree-symlink-isolation.md` · GitHub Issue #17 / #7

## Global Constraints
- Proibição absoluta de `git stash` e `git stash pop`.
- Sanitização rigorosa de identificadores de swarm para prevenir ataques de path traversal.
- Idempotência: caso o symlink de destino já exista ou aponte corretamente para a raiz, atualizar ou ignorar sem lançar erro fatal.
- Resiliência / Soft degradation: se uma pasta de dependências candidata não existir na raiz (por exemplo, um projeto TypeScript puro sem pasta `.venv/`), ignorar elegantemente e ligar apenas as pastas que existirem.
- Testes unitários e de integração executados em diretório temporário isolado (`std::env::temp_dir()`).
- Commits atómicos em conformidade estrita com Conventional Commits 1.0.0.

## Review Focus
1. **Broken Symlink Handling**: Se o worktree for criado após remoção manual do diretório alvo na raiz, o symlink não deve travar o processo nem causar panic.
2. **Platform Compatibility**: Usar `#[cfg(unix)]` com `std::os::unix::fs::symlink` no macOS/Linux e fallback seguro ou `#[cfg(windows)]` para evitar falha de compilação cross-platform.
3. **Circular Link Prevention**: Garantir que as pastas de worktree (`.helm/worktrees/*`) nunca criem symlink recursivo para o próprio `.helm`.
4. **Permissions & Metadata**: Verificar se os ficheiros de dependência são lidos transparentemente na worktree através do link simbólico.
5. **Clean Worktree Teardown**: Na remoção do worktree, os symlinks devem ser removidos sem apagar o conteúdo dos diretórios originais na raiz do projeto.

**Interfaces:**
- Consumes: `Path`, `PathBuf`, `std::fs`, `serde::Serialize`, `serde::Deserialize`
- Produces:
  ```rust
  #[derive(Debug, Serialize, Deserialize, Clone, PartialEq, Eq)]
  pub struct SymlinkEntry {
      pub name: String,
      pub source: String,
      pub target: String,
      pub success: bool,
      pub error: Option<String>,
  }

  pub fn link_dependencies(repo_root: &Path, worktree_dir: &Path) -> Result<Vec<SymlinkEntry>, String>;
  pub fn unlink_dependencies(worktree_dir: &Path) -> Result<(), String>;
  ```

- [ ] **Step 1: Escrever teste de ciclo de vida de symlinks em repositório temporário**
